# 🏗️ Env-Guard System Architecture & Technical Design

เอกสารนี้อธิบายรายละเอียดเชิงเทคนิคและสถาปัตยกรรมภายใน (Internal Architecture) ของระบบ **Env-Guard**

---

## 1. High-Level Architecture Overview

ระบบทำงานเป็นแบบ **Pipeline Architecture (สตรีมแบบทางเดียว)** เพื่อประสิทธิภาพความเร็วสูงสุดระดับมิลลิวินาที:

```
+-------------------------------------------------------------------+
|                           CLI Runtime                             |
+-------------------------------------------------------------------+
          |                                       |
          v                                       v
+-------------------+                   +-------------------+
|  Code Scanner     |                   |  Env File Parser  |
|  - File Crawler   |                   |  - Lexer/Tokenizer|
|  - Ignore Filter  |                   |  - AST Formatter  |
|  - Regex Matcher  |                   |  - Secret Audit   |
+-------------------+                   +-------------------+
          |                                       |
          +------------------+--------------------+
                             |
                             v
                 +-----------------------+
                 |      Diff Engine      |
                 |  - Set Operations     |
                 |  - Classifier         |
                 +-----------------------+
                             |
                             v
                 +-----------------------+
                 |    Action Dispatcher  |
                 |  - Console Reporter   |
                 |  - File Mutator (Fix) |
                 |  - Schema Exporter    |
                 +-----------------------+
```

## 2. Core Modules & Data Structures

### 2.1 Code Scanner Module
- **หน้าที่**: ค้นหาไฟล์ในโปรเจกต์และดึงชื่อตัวแปรทั้งหมด
- **Data Structure**:
  ```typescript
  interface ScannedKey {
    name: string;        // เช่น "STRIPE_KEY"
    filePath: string;    // เช่น "src/billing/service.ts"
    lineNumber: number;  // เช่น 42
    snippet: string;     // เช่น "const key = process.env.STRIPE_KEY;"
    language: string;    // "typescript" | "python" | "go"
  }

  type CodeScanResult = Map<string, ScannedKey[]>; // KeyName -> รายการจุดที่เรียกใช้
  ```

### 2.2 Env File Parser & Preserver Module
- **ปัญหา**: ปัญหาใหญ่ของ linter หลายตัวเวลาสั่ง auto-fix คือการเขียนทับไฟล์จน Comment และการเว้นวรรคหายหมด
- **วิธีแก้**: ใช้ Tokenizer ที่เก็บประวัติบรรทัดเดิมแบบ 1:1
- **Data Structure**:
  ```typescript
  type EnvLine = 
    | { type: 'comment'; raw: string }                  // เช่น "# Database Configurations"
    | { type: 'empty' }                                  // บรรทัดว่าง
    | { type: 'entry'; key: string; value: string; raw: string }; // เช่น "PORT=3000"

  interface ParsedEnvFile {
    filePath: string;
    lines: EnvLine[];
    keySet: Set<string>;
  }
  ```

### 2.3 Diff Engine Module
- **อัลกอริทึมการเปรียบเทียบ**: ใช้ Set Difference Operation มาตรฐาน `O(N + M)`:
  - `Missing Keys = CodeKeySet \ EnvKeySet`
  - `Zombie Keys = EnvKeySet \ CodeKeySet`
  - `Synced Keys = CodeKeySet ∩ EnvKeySet`

## 3. Secret Leak Prevention Algorithm

การตรวจจับ Secret ไม่ได้พึ่งพาเพียงแค่ Regex ชื่อตัวแปร แต่ใช้ **Dual-Layer Inspection**:

1. **Known Pattern Matching (ความแม่นยำสูง)**:
   - ตรวจจับ Prefix ของ Service Provider ยอดนิยม:
     - Stripe: `sk_live_[0-9a-zA-Z]{24}`
     - GitHub: `ghp_[0-9a-zA-Z]{36}`, `gho_...`
     - AWS: `AKIA[0-9A-Z]{16}`
     - Google: `AIza[0-9A-Za-z-_]{35}`
     - JWT Token: `^[A-Za-z0-9-_=]+\.[A-Za-z0-9-_=]+\.?[A-Za-z0-9-_.+/=]*$`
     - RSA/SSH Private Keys: `-----BEGIN [A-Z ]+ PRIVATE KEY-----`

2. **Shannon Entropy Analysis (ตรวจจับ Random Secrets)**:
   - สำหรับค่าที่ไม่มี prefix ชัดเจน แต่เป็นสตริงแบบสุ่มสูง (เช่น random hash หรือ secret salt):
   - สูตรคำนวณ Shannon Entropy:
     $$H(X) = -\sum_{i=1}^{n} P(x_i) \log_2 P(x_i)$$
   - หากความยาวสตริงเกิน 16 ตัวอักษร และมีค่า Entropy สูงกว่าเกณฑ์ (Threshold > 4.5) ระบบจะจัดว่าเป็น **Suspicious Secret Leak** ทันที

## 4. Safe Auto-Fix Strategy (Non-Destructive Write)

เมื่อผู้ใช้สั่ง `env-guard fix`:

1. อ่านไฟล์ `.env.example` เดิมเข้ามาเป็น List of `EnvLine`
2. หา Missing Keys ทั้งหมด
3. ทำการเพิ่ม Missing Keys เข้าไปต่อท้ายไฟล์ โดยเติมเป็นหมวดหมู่ใหม่:
   ```env
   # -------------------------------------------------------------
   # [Auto-generated by env-guard] - Please provide sample values
   # -------------------------------------------------------------
   STRIPE_WEBHOOK_SECRET=""
   REDIS_URL=""
   ```
4. ในกรณีที่ใส่ธง `--prune`:
   - ทำการกรองบรรทัดที่มีประเภทเป็น `entry` และ key อยู่ในกลุ่ม `Zombie Keys` ออกจากไฟล์
   - Comment ที่อยู่เหนือ Zombie Key จะถูกพิจารณาเก็บไว้หรือลบออกตามการตั้งค่าความปลอดภัย

## 5. Performance Benchmark Targets

* **เป้าหมายความเร็ว**:
  - โปรเจกต์ขนาดเล็ก (< 100 ไฟล์): **< 5ms**
  - โปรเจกต์ขนาดกลาง (1,000 ไฟล์): **< 20ms**
  - โปรเจกต์ขนาดใหญ่ (10,000 ไฟล์): **< 150ms**
* **Memory Footprint**: ใช้ RAM ไม่เกิน **15MB - 30MB** ขณะทำงาน
